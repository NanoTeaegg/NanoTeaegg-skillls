# UI 设计系统自检清单

产出前快速检查:

## 平台范围

- 是否明确只服务一个目标平台?
- 如果上游技术方案有多个平台,是否询问或记录了本次目标平台?
- 文档中是否混入了其他平台专属组件或交互习惯?

## 上游对齐

- 是否读取或说明缺失 `docs/PRD.md`、`docs/UX.md`、`docs/TECH_DESIGN.md`?
- 页面级 UI 规则是否来自 UX 的页面结构,而不是重新发明流程?
- 技术方案中的平台范围是否被尊重?

## Token 结构

- 是否保留颜色、文字、间距、圆角/边框/阴影、层级/动效、图标/图表分类?
- token 是否有语义用途和注意事项,而不是只给值?
- token 是否有代码映射,并与设计系统代码一致?
- token 值是否和产品气质、信息密度、目标平台一致?

## 三类产物

- 是否同时产出 UI_SPEC、设计系统代码和设计系统文档站点?
- 变更时三类产物是否同步更新?
- HTML 文档站点是否有左侧导航,并按全局变量、基础组件、业务组件/模式分组?
- 右侧内容是否包含规范文本、Dos and Don'ts、代码展示和视觉预览?
- 颜色、字体、间距、圆角/阴影是否有独立文档章节?
- 是否支持浅/深色切换,并尽量提供可编辑示例?

## 组件与状态

- 组件是否按「API、变体、状态、Token 依赖、禁止用法」写?
- loading、空态、错误态、禁用态、成功态是否有统一视觉规则?
- 文档站点是否展示常用状态?

## AI 落地约束

- 是否明确业务代码只能使用设计系统 token、组件、变体和 pattern?
- 是否禁止裸色值、裸 px、临时 CSS 或临时组件样式?
- 是否写明组件缺口处理方式:复用、增加变体或新增组件?
- 新增组件或影响面大的变更是否需要通知用户?

## 边界

- 是否只写设计系统基础代码,避免写业务页面代码?
- 是否避免数据库/API/部署/状态管理等非 UI 方案?
- 是否避免重写 PRD/UX?
- 是否记录开放问题和变更记录?
