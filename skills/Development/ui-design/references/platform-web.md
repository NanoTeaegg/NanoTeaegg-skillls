# Web UI 规范参考

适用于 Web 后台、SaaS、浏览器应用、桌面 Web 管理端。

## 平台重点

- 优先信息密度、扫描效率、批量操作和键盘可达。
- 页面通常由侧边导航/顶部导航、工具栏、主内容区、浮层组成。
- 表格、筛选器、表单、弹窗、Toast、图表是高频组件。
- 响应式应明确断点和降级策略,不要只写"适配移动端"。

## 布局规则

- 管理后台默认使用左侧导航 + 顶部上下文栏 + 主内容区。
- SaaS 工作台可使用顶部导航 + 内容栅格。
- 列表页:筛选区、批量操作、表格、分页层级要固定。
- 详情页:主信息、状态、操作区、关联信息分组清楚。
- 移动 Web:表格需要降级为摘要卡片或横向滚动,不要照搬桌面表格。

## Web 组件清单

至少按需覆盖:

- 导航:侧边栏、顶部栏、面包屑、标签页。
- 按钮:主按钮、次按钮、文本按钮、危险按钮、图标按钮。
- 表单:输入框、选择器、日期范围、校验、帮助文本。
- 表格/列表:列宽、密度、hover、focus、选中、排序、分页、空态。
- 卡片:指标卡、内容卡片、状态卡片。
- 弹窗/抽屉/Popover:确认、编辑、详情、筛选。
- Toast/通知:成功、警告、错误、异步任务。
- 图表:颜色语义、图例、tooltip、空态。

## Web 可访问性

- 键盘 focus 必须可见,且不被 hover 样式覆盖。
- 错误态不能只靠红色;需要字段级或区域级文案。
- 表格要支持横向扫描:数字右对齐、状态列固定语义。
- 图表需要图例、tooltip 或文本摘要辅助理解。

## Web 禁区

- 不要写 iOS 导航栏、Android Material 专属组件。
- 不要输出 React/Vue/Tailwind 代码。
- 不要替 dev-kickoff 选择 shadcn/ui、Ant Design、MUI 等组件库。
